# スズリ 基本設計

## 目的

日本語の文を一文まるごとひらがなで入力し、マウス操作（ピンのドラッグとホイール）で一気に変換して、結果をクリップボードに入れるツール。
普段の IME で起きる「候補を切り替えると後ろの文が動く」「漢字を見て読みを思い出す」負担をなくすことを狙う。

## 対象環境

- Windows と macOS。最初に Windows で動かし、macOS も同じ設計のまま対応する
- OS ごとに異なる処理は `platform` モジュールに閉じ込め、`cfg(target_os)` で切り替える

## 技術構成

| 層 | 採用 | 役割 |
|---|---|---|
| アプリ枠 | Tauri 2 | ウィンドウ、グローバルショートカット、クリップボード、トレイ常駐 |
| UI | React + TypeScript（Vite） | オーバーレイの描画とマウス・キー操作 |
| 変換エンジン | Rust（独立 crate） | 辞書引き、文節区切り、候補生成、学習 |
| 辞書 | Mozc OSS 辞書 | ビルド時に取得してバイナリ化し、アプリに同梱 |

### ディレクトリ構成（予定）

```
suzuri/
  CLAUDE.md
  docs/design.md
  Cargo.toml              # workspace
  crates/
    suzuri-engine/        # 変換エンジン。Tauri に依存しない
    suzuri-dictgen/       # Mozc 辞書の取得とバイナリ化
  src-tauri/              # Tauri アプリ本体（エンジンを呼ぶ薄い層 + platform）
  src/                    # フロントエンド（React）
```

エンジンを Tauri から切り離すのは、UI なしでテストとベンチマークを回すため。

## 画面

ショートカットで呼び出すと、画面中央にオーバーレイが出る。

- マウスカーソルがあるモニターの中央に出す
- 大きさは固定値（900×560）。実際に使いながら調整する
- 枠なし・最前面・タスクバー（Dock）に出さない
- 常駐し、トレイ（メニューバー）のメニューから「開く」・「起動時の入力モード」の選択・「ログイン時に起動」の切り替え・「学習をリセット」・「終了」を行う
- ウィンドウは起動時に1つだけ作り、表示と非表示を切り替えて使い回す（毎回作ると WebView の起動待ちが出るため）
- 閉じるときは画面を空にし、パネルごと消してウィンドウを丸ごと透明にして、描き終えてから隠す。隠した WebView は描き直さないため、そのまま隠すと次に出したときに前の内容が一部残って見える（macOS で起きた）。中身を空にするだけでは 0.2.0 でも残ったので、パネルも消す。最後の絵が透明なら、次に出した瞬間に移す前の位置（前のディスプレイ）に出ても何も見えない
- 出すときは、"summon" を受けて新しい状態を描き、さらに1フレーム待ってからパネルを見せる（ウィンドウの移動が反映されるまで透明にしておく）。描き終えるのを待つのは長くても 50ms で打ち切る。調べるため、閉じるときと出すときに、描画の通知で抜けたか打ち切ったかを標準エラーに出す（`[overlay] close: raf` など）
- Alt+F4 などで閉じられたときも、Rust で直接隠さず、画面側に知らせて Esc と同じ経路で閉じる
- macOS で貼り付けのためにアプリを隠すときは、先にオーバーレイを隠す。出ていたまま隠すと、次に呼び出してアプリを表に戻した瞬間に前の位置で出てしまう。出すときも、位置と大きさを置き直してからアプリを表に戻す

### レイアウト

```
     ↓ピン   ↓      ↓
 わたしは｜きょう｜がっこうに｜いきます      ← ひらがなの行（読みとピン）
 私は      今日    学校に      行きます      ← 候補の行（各文節の今の候補）
 ……（折り返すと、ひらがなの行と候補の行が交互に続く）
```

- 文節ごとに、ひらがな（上）と今の候補（下）を縦に積んだ箱にし、箱を横に並べて文節の切れ目で折り返す。行を重ねると、ひらがなの行と候補の行が交互に並ぶ。対応する文節を上下の近くで見られるように、0.2 までの上下に分けた形（上段にひらがな、下段に変換結果）から替えた（`ui-interleaved` ブランチで試している）
- 箱の幅はひらがなと候補の長い方になる。ひらがなと候補は、どちらも箱の中央にそろえる（短い方の両側が空く）。ただし最後の文節（ふつうは打っている文節）だけは左にそろえる。中央だと、打つたびに文字が左右に動いて見づらいため。箱は途中で折り返さないので、文節が行をまたがない。行の幅より長い文節だけは、箱の中で折り返す
- 改行の文節は箱に入れず、そのまま行を改める
- ひらがなの行と候補の行は、文字の大きさと濃さで見分ける。ひらがなは小さめ（22px）、候補は大きく（26px）濃い太字にする
- 候補の行には区切りの線やピンを出さない。箱と箱の間はピンの幅だけ空くので、文節の切れ目はそれで分かる。上下に分けていたときは、対応する文節を示すため文節ごとに青とオレンジの下線を交互に引き、マウスを重ねると上下の両方を強調していたが、同じ箱で上下に並ぶので、どちらもやめた。マウスを重ねたときは、乗っている行だけを強調する
- ピンはオレンジにし、足を候補の行の下端まで伸ばす。入力カーソルや登録の知らせが青なので、青にすると見分けにくい。オレンジは暗い背景でも沈まない。上下に分けていたときは、文節の下線（青・オレンジ）と見分けるため赤紫にしていた
- はみ出したら縦にスクロールする
- 入力カーソルは青い縦線で、文字の並びを変えない（左右の文字と離すのも試したが、やめた）。打ったり動かしたりした直後は点いたままにし、0.8 秒たってから点滅させる（↑↓で候補の行を飛び越えて動くと見失いやすいため）。矢印キーやクリックで動かしたときは、動かした先で一瞬光らせてから細い線に戻す。滲みは、入力カーソルを中心にした縦長の楕円（中心から外へ薄くなる。0.45 秒で消える）と、入力カーソルのまわりの影（全体に弱く、縦に強く。0.35 秒で消える）を重ねる。楕円だけだと入力カーソルとの境目が見える。入力カーソル自体も少し太く、縦にも少し伸ばす（打ったときは光らせない。打つたびに光ると邪魔）
- 打ったり入力カーソルを動かしたり文節の区切りが変わったりしたら、入力カーソルのある文節の箱を、候補の行まで見える範囲に入れる（長い文で最後の行が隠れないように）。候補を替えただけでは動かさない
- 配色はライトとダークがあり、トレイメニューの「外観」で「OS に合わせる」「ライト」「ダーク」から選ぶ（既定は OS に合わせる）。選んだものは `settings.json` に保存し、各ウィンドウにイベントで知らせる。画面側はルートの `data-theme` に light か dark を入れ、色は CSS の変数で切り替える。OS に合わせるときは OS 側の切り替えにもついていく。ダークではピンを同じ色相のまま明るくし、暗い背景で沈まないようにする
- 設定画面で、文字の大きさ（標準の 70〜200%）と背景の不透明度（30〜100% を 5% 刻み、既定 85%）を変えられる。不透明度を下げると、うしろの画面を透かして見ながら打てる。設定は `settings.json` に保存し、オーバーレイは起動時に読んでおき、変えたときはイベントで受け取る。つまみを動かしている間は保存せず、止めて 0.3 秒たったら保存する
- オーバーレイは、上の中央の掴みどころ（灰色のカプセル。線を入れると引き下ろせるように見えるので、カプセルだけにする）・余白・下の案内の欄をドラッグして動かし、縁をドラッグして大きさを変えられる。文字の上はピンや文節の操作に使うので動かさない
- パネルの縁はグレーの線にする（ライトは暗いグレー、ダークは明るいグレー）。0.2 までは縁から 12px かけて透明へ溶かしていたが、やめた
- 大きさを変える掴みどころは、ウィンドウの縁とパネルの間の透明な余白（8px）と、パネルの縁の内側にまたがって置き、見た目の縁より少し外を押しても掴めるようにする。Windows の透明なウィンドウは完全に透明なところのクリックを後ろのアプリに渡すので、掴みどころには見えないほどわずかに色を付ける
- 掴みどころは見て分かるようにする。印はどれもパネルの縁から内側にだけ描き、外側の輪郭は滑らかなままにする。四隅（幅と高さの両方を変えられる）には、縁を内側に太らせた印をいつも出す。印の内側の輪郭は、辺から 60° で内へ入り、角の点を中心にした扇の弧を通って、もう一方の辺へ 60° で戻る（対角線の上で約 5px 太る）。辺（幅か高さの一方だけ）は、マウスを乗せたときだけ辺に沿って内側に太い線を出す。マウスを乗せた掴みどころは青にする
- 動かしている間・大きさを変えている間は OS の処理に入って画面からフォーカスが外れるが、ウィンドウ自体は前面のままなので閉じない。画面のフォーカスが外れたら OS にウィンドウが前面かを問い合わせ、前面でなくなっていたときだけ閉じる。縁の数 px はウィンドウのライブラリが組み込みで大きさ変更を始めるので、画面側では操作の始まりを知れず、フラグでは見分けられない
- 大きさの変更はまず OS に任せる。macOS は枠のないウィンドウの大きさ変更を OS に任せられないので、ポインターの動きから自分で大きさと位置を変える
- 位置を覚えるかは、表示したときに置いた位置と隠すときの位置を比べて決める。macOS は論理ピクセルで置くため 1px ずれて読めることがあり、2px までのずれは動かしていないとみなす
- 手で動かした位置と変えた大きさは、隠すときにそれぞれ `settings.json` に覚え（確定を待たせないよう別スレッドで保存）、次から同じところに出す。位置はモニターごとに、そのモニターの左上からの距離で覚え、隠すときにウィンドウがいるモニターの分として保存する。出すときはマウスのあるモニターで覚えた位置に出し、そのモニターで動かしていなければその中央に出す。大きさはモニターによらず1つで、変えていなければ既定の大きさで出す。覚えた位置がどのモニターにも入らないときも中央に出す
- モニターは名前・配置・解像度の組で見分ける。同じ機種を並べても分かれ、配置や解像度を変えたモニターは別のモニターとして扱う（覚えた位置ははみ出しうるので使わない）
- 掴みどころにマウスが乗っている間は、左下の案内を「ドラッグで移動」「ダブルクリックで中央に戻す」に替える
- 掴みどころの左に「a」（英数）、右に「あ」（かな）を置き、今の入力モードを塗りつぶして示す。押すとそのモードにする。押してもフォーカスは取らない（Enter や Space で押されないように）。マウスが乗っている間は、左下の案内を切り替えのキーの説明に替える
- 掴みどころを続けて2回押すと、大きさはそのままで今いるモニターの中央に戻し、そのモニターで覚えた位置を忘れる。1回目で OS の移動の処理に入るためダブルクリックのイベントは届かないので、押した間隔（0.4 秒以内）で見分ける
- 設定画面の「元に戻す」で、すべてのモニターで覚えた位置と大きさを忘れる
- 当初は文節ごとに上下を同じ幅の列にそろえていたが、変換後の文を区切りなしで読めるほうを優先して分けた

## 操作

### 流れ

1. ショートカットで呼び出す
2. ローマ字で一文を入力する。ひらがなの行に表示され、打つそばから変換する（ライブ変換）。推奨の文節区切りにピンが立ち、各文節の下に変換結果が出る
3. 入力中は、打っている文節とその1つ前の文節を区切り直す（「くるま」の時点の区切りで「車｜で」と割れたままにならないように）。それより前の文節と、手で置いた・動かしたピンは変えない
4. ピンと候補を調整する（下の表）
5. Enter で確定する。完成形をクリップボードに入れてオーバーレイを閉じる。貼り付けモードなら、呼び出し元の入力欄に貼り付けるところまで行う

Esc はクリップボードに入れずに閉じる。オーバーレイの外をクリックするなどしてフォーカスが外れたときも、Esc と同じく閉じる。どれで閉じても、閉じる直前の状態を「前回」として保存する。Esc のときは呼び出し元にフォーカスを戻す（macOS はウィンドウを隠すだけではスズリが前面に残ることがあるため）。フォーカスが外れて閉じたときは、移った先に任せて戻さない。

### Enter のモード

画面右下のモードの表示を押して、2つのモードを切り替える（押してもフォーカスは取らない）。最後に使ったモードを次回も使う。当初は Tab で切り替えていたが、Tab は続きの予測（サジェスト）を採るのに使うことにした。初めて起動したときは貼り付けモード。

| モード | Enter で起きること |
|---|---|
| コピー | クリップボードに入れて閉じる |
| 貼り付け | クリップボードに入れて閉じ、呼び出す前に前面にあったウィンドウにフォーカスを戻して Ctrl+V（macOS は Cmd+V）を送る |

- 戻り先は、ショートカットを押した時点で前面にあったウィンドウ。トレイから開いたときは戻り先がないので、コピーだけになる
- 戻り先のウィンドウが閉じられていたり、キーを送る直前に前面が別のウィンドウに変わっていたりしたら、貼り付けはせずコピーだけにする（意図しないウィンドウ、たとえばターミナルに貼り付けないため）
- 貼り付けたあとは、既定ではクリップボードを貼り付ける前の中身に戻す（設定画面の「貼り付けたあともクリップボードに残す」で残せる。`settings.json` の `keepPastedInClipboard`）。キーを送ってから 500ms 待って戻す。早く戻すと、貼り付け先がクリップボードを読む前に戻って元の中身が貼られる。待つ間にほかのものがコピーされていたら戻さない。戻せるのは文字だけで、元が文字でなかった（空・画像など）ときはクリップボードを空にする
- キーを送れなかったとき（戻り先がない・前面が変わった・送信に失敗した）は、手で貼れるようクリップボードに残す
- コピー操作のキー（Ctrl+C）は送らない。クリップボードへは API で直接書く
- フォーカスを戻してからキーを送るまで 100ms 待つ。戻りきる前に送ると空振りするアプリがある
- 管理者権限で動くアプリには、Windows の仕組み上キーを送れない（コピーだけになる）

### 続きの予測（サジェスト）

`ui-interleaved` ブランチで試している。

- 打っている長い語の続きを1つだけ出す（「あにめー」→「アニメーション」）。入力カーソルが読みの末尾にあり、打ちかけのローマ字がなく、変換結果が読みの末尾までそろっているときに探す
- 出すのは読みが7文字以上の語だけ（`MIN_WORD_CHARS`）。文節（助詞などを含むもの）は出さない。短い語は続きを読んで選ぶより打つ方が早く、読む間が打つ流れに挟まる。文節は「てにをは」まで当てる必要があって外れやすい
- 語の始まりは最後の文節の先頭とし、見つからなければ1つ前の文節の先頭（打っている途中で「アニメ｜ー」と割れることがある）から探す。空白や改行のあとは探さない
- 最後の文節の候補の行にだけ薄く出し、「Tab」の印を添える。続きの語がかかる文節（打っている途中で「アニメ｜ー」と割れていればその両方）の今の候補をつないだもの（「アニメー」）で語の表記が始まれば、足す部分（「ション」）だけを出す。そうでなければ、かかる文節の候補を隠して語の表記を出す。ひらがなの行には出さない（読む行を増やさないため）。Tab で採ると、ひらがなの行と候補の行の両方に足される
- Tab で採る。読みの末尾に続きのかなを足し、語の始まりから末尾までを1文節にして、語の表記を選ぶ
- 出どころと順: ユーザー辞書の語（新しく登録した順）→ 学習した語（新しく使った順）→ システム辞書。学習データは文節で覚えているので、システム辞書に同じ読みと表記の名詞があるものだけを使う。ユーザー辞書は英字の大文字・小文字や記号の書き方をそろえて比べる
- システム辞書からは、採られそうなときだけ出す。比べるのは出せる語（読み7文字以上の名詞で、2文字以上を補い、続きが小さいかなで始まらないもの）どうしで、次のどれかに当たれば出さない
  - 3文字打つまで（短いと関係のない語が出やすい）
  - 打った読みで始まる読みが 300 を超える（どれか分からない。探す時間の上限にもなる）
  - いちばんコストの低い語のコストが 5000 を超える（よく使う語に限る）
  - 2番目の語とのコストの差が 500 未満（迷う）
  - 打った読みそのものが、続きの語よりコストで 1500 以上低い（ずっとよく使う）語になっている（「わたし」→「私の男」）
  - 短い語（「あにめ」に対する「アニメ」、「こんぽ」に対する「根本」）は迷う相手に数えない。数えると短い語の方がよく使われるので3文字では出せず、出るのが遅く感じた。代わりに「アニメ」と打つつもりでも「アニメーション」の続きが薄く出る（打ち続ければ消える）
  - 名詞でない語（「サジェストすれ」は「サジェストする」の活用形）、固有名詞（人名・地名・組織名）、接尾・非自立の名詞、数、代名詞と、英字だけの表記（「いんたー」→「IC」）は数えない。名詞かは語の末尾の品詞（右文脈ID）で見る。辞書に名詞の印を持たせる（形式 `SZRDIC04` の8つ目の領域）
- 実際の辞書で、3文字で「あにめ」→アニメーション、「こんぽ」→コンポーネント、「いんた」→インターネット、「めーる」→メールアドレス、「すまー」→スマートフォンを出し、「わたし」「かいぎ」「ありが」「きょう」では出さないことを確かめた。学習1万件・ユーザー辞書1000語の状態でも、1回の探索は最大 0.9ms（辞書だけなら 0.2ms）

### 編集のキー

| キー | 結果 |
|---|---|
| Backspace・Delete | カーソルの前・後ろの1文字を消す。Delete は打ちかけのローマ字を先に確定させてから消す |
| Ctrl+Backspace・Ctrl+Delete（macOS は Option） | カーソルの前・後ろを文節の区切りまでまとめて消す。打ちかけのローマ字があれば、それだけを消す |
| Cmd+Backspace・Cmd+Delete（macOS だけ） | カーソルの前・後ろを先頭・末尾まで消す |
| ←→・Home・End | カーソルを動かす |
| ↑↓ | カーソルの横の位置のまま、上・下の行の一番近い文字の間に動かす。上・下に行がなければ先頭・末尾に動かす |
| Shift+Enter | 改行を入れる（Enter だけなら確定）。改行は空白と同じく、それだけで1文節にする。改行の前後は行が変わって区切りが明らかなので、ピンを出さない（区切りとしては残り、ほかのピンはそこを越えて動かせない） |
| F6〜F10 | マウスを乗せている文節を、ふつうの IME と同じく、ひらがな・全角カタカナ・半角カタカナ・全角英数・半角英数に書き換える。マウスを乗せていなければ何もしない。英数にするときは、打った打鍵を覚えていないので、読みのかなからヘボン式寄りのローマ字に戻す（し → shi、っ は次の子音を重ねる、ん は母音・や行・な行の前で nn）。英字だけの読みは、F6〜F8 ではローマ字として読んでかなにする。候補にない書き方は候補の最後に足して選ぶ |

Ctrl+V（macOS は Cmd+V）で、クリップボードの文字をカーソル位置に貼り付ける。ローマ字にはせず、漢字も英字もそのまま読みに入れる（辞書にない文字は、エンジンがそのままの表記で1文字ずつ通す）。改行は \n にそろえ、タブは空白にし、ほかの制御文字は捨てる。クリップボードは Rust 側から読む。貼り付けた漢字はホイールでほかの候補に変えられない。長い文を貼ると、打鍵ごとの変換は文の長さに比例して遅くなる。

### ショートカット（既定値。設定で変更可能）

トレイの「設定…」で開くウィンドウで変える。欄を押してから使いたい組み合わせを実際に押すと記録し、その場で登録を試す。ほかのアプリや OS が使っていて登録できなければ、元のままにして理由を出す。Ctrl・Alt・Cmd のどれも含まない組み合わせは、普段の打鍵を奪うので受け付けない。記録している間は登録を外し、今のショートカットも押せるようにする。設定は `settings.json` に保存する。

| 操作 | Windows | macOS |
|---|---|---|
| 新規入力で呼び出す | `Alt+J` | `Option+J` |
| 前回を編集する | `Alt+Shift+J` | `Option+Shift+J` |

J は標準のメニューでほぼ使われず、ホームポジションで押せるため選んだ。代わりに次のものが使えなくなる。

- JetBrains 系 IDE の `Alt+J`（次の同じ語を選択）と `Alt+Shift+J`
- macOS で `Option+J` で打つ「∆」

`Alt+Space` は Windows のウィンドウメニューや PowerToys Run と、`Alt+V` はメニューバーの「表示」と重なるため避けた。macOS は実機で確かめてから確定する。

「前回を編集する」で呼び出すと、前回のひらがな・ピン・選んだ候補をそのまま復元する。保存する前回は当面1件だけ。

### マウス操作

| 操作 | 結果 |
|---|---|
| ピンをドラッグ | 文節を伸縮する。ピンは文字と文字の間に吸着する。離した時点で変換結果を更新する |
| 文字の間を右クリック | ピンを追加する。macOS は右クリックのメニューのイベントがボタンを押したときに来るので、ボタンを離したときに追加する |
| ピンを右クリック | ピンを削除し、両側の文節を1つにまとめる。ボタンを離したときに消す（押したまま 4px 以上動かしたら、下の右ドラッグに移るため） |
| ひらがなの文字かピンを右ボタンでドラッグ | 選んだ範囲を1つの文節にする。ピンから始めたときは、ピンの位置が範囲の端になる。ドラッグ中は範囲を強調し、離した時点で確定する。範囲の内側の区切りは外し、両端を手で置いた区切りにする。端が文節の途中だったら、外に残った部分をその外隣の文節とあわせて自動で区切り直す（残りが助詞だけになったときに隣に付けられるように。手で置いた区切りは越えない）。動かさずに離したときは、文字の間を右クリックしたのと同じくピンを追加する |
| ピンのドラッグ・右ドラッグ中にパネルの左右の端を越える | ポインターを反対側の端へ移す（越えた分だけ内側に入れる）。ドラッグしていないときは移さず、ウィンドウの外へ出られる（縁での大きさ変更や枠外クリックで閉じるため） |
| 文節（ひらがな・候補どちらでも）にマウスを重ねる | 乗っている行（ひらがなか候補）だけを強調表示する |
| 文節にマウスを重ねてホイール | 候補を切り替える。下回しで次の候補。切り替え中は候補の行の文節の近くに小さな候補一覧を出し、文節からマウスが離れるまで残す。マウスのホイールは1目盛りで1候補、トラックパッドは量をまとめて送る（向きが変わるか 0.3 秒止まったら、まとめかけの量は捨てる） |
| 候補の行の文節を左ダブルクリック | その文節の今の表記を、ひらがなの行（読み）にそのまま書き込み、入力カーソルをその後ろに置く。読みを知らない漢字を、知っている読みの語から切り出すため（「あかるい」→「明るい」を書き込み、「るい」を消して「明」を残す）。書き込んだ文字は貼り付けた漢字と同じく、ホイールでほかの候補に替えられない。区切りは変えずに変換し直し、書き込んだ文節は書き込んだ表記を選ぶ（「明るい」のままだと「明｜類」になるため）。打ちかけのローマ字があるときは何もしない |
| 文節の外でホイール | 何もしない。入力が長くてはみ出したときも、ホイールだけではスクロールしない |
| Ctrl+ホイール（パネルのどこでも） | ひらがなと候補の領域をスクロールする。候補は切り替えない |
| ひらがなと候補の領域を左クリック | 一番近いひらがなの文字の間に入力カーソルを置く。候補の行を押したときも、縦に一番近いひらがなの行に置く。文字の上でなくても（行の右の余白や最後の行の下でも）、縦に一番近い行の中で横に一番近い文字の間に置く。ピンの上は、押してから 0.3 秒より短く離し、動きが 4px より小さかったときだけクリックとみなしてピンの位置に置く（それ以外はピンのドラッグ） |

### 変換後の挙動

- ピンを動かしても範囲が変わらない文節は、選んでいた候補をそのまま残す。第1候補のままだった文節は残さず、新しい第1候補にする（学習で順が変わったときに、前の第1候補が2番目以降として選ばれたまま残らないように）
- 候補リストの最後には、ひらがなのまま・カタカナの候補を必ず入れる
- 変換後にキーボードでひらがなを直したら、直した文節だけ区切りと候補を計算し直す
- 打つそばから変換するときは、直した文節に加えて、1つ前の文節と、打った位置から12文字以内に始まる文節を区切り直す（`RETYPE_WINDOW`）。1つ前までだと、打っている途中にできた区切り（「あにめー」の時点の「アニメ｜ー」）が残り、まとめて変換すれば1語になる語や区切りの学習で覚えた語が使えないため。それより前は、打つたびに入れ替わってちらつかないよう触らない。手で置いたピンと、候補を選んだ文節の両端は越えない（選んだ候補を保つ）

## 変換エンジン

### 辞書

- Mozc の OSS 辞書（`src/data/dictionary_oss/`）を使う。形式は「読み・左文脈ID・右文脈ID・コスト・表記」と、品詞同士の接続コスト表
- リポジトリには入れない。`suzuri-dictgen` がビルド時に、固定したコミットの辞書をダウンロードし、ハッシュ値を照合してからバイナリに変換する
- 取得した元データは `.cache/` に置き、2回目以降のビルドはオフラインで済む
- バイナリ辞書はアプリのリソースとして同梱し、起動時にメモリマップで読む
- 配布物には Mozc と IPAdic のライセンス表記を含める

### 処理

1. 読みの各位置から辞書を前方一致で引き、単語の候補を並べる（ラティス）
2. Viterbi で、単語コストと接続コストの合計が最小の並びを求める
3. 自立語で新しい文節を始め、助詞・助動詞などの付属語は直前の文節に付けて、文節に区切る。判定には Mozc の `segmenter.def` を使い、数字・助数詞・「第」などの数のまとまり（「3時」「第2」）は区切らない規則を優先して足す
4. 文節ごとに、その範囲に限って上位の候補を複数求める

### インターフェース

```rust
/// 読みを自動で文節に区切り、各文節の候補を返す
fn convert(&self, reading: &str, history: &UserHistory) -> Conversion;

/// ユーザーが決めた区切り（文字位置）に従って、各文節の候補を返す
fn convert_with_boundaries(&self, reading: &str, boundaries: &[usize], history: &UserHistory) -> Conversion;

/// 区切りは保ったまま、range の内側だけ自動で区切り直す（ひらがなを直したとき）
fn resegment(&self, reading: &str, boundaries: &[usize], range: Range<usize>, history: &UserHistory) -> Conversion;

/// 区切りは保ったまま、ranges のそれぞれの内側だけ自動で区切り直す（右ドラッグで選んだ範囲を1文節にしたとき）
fn resegment_ranges(&self, reading: &str, boundaries: &[usize], ranges: &[Range<usize>], history: &UserHistory) -> Conversion;

/// 確定した文節を学習する
UserHistory::commit(&mut self, committed: &[Committed]);
```

ローマ字からひらがなへの変換はフロントエンド側（TypeScript）で行う。打鍵ごとに Rust を呼ばずに済むため。

打ちかけのローマ字が次の打鍵で確定したあと（`t` `k` で「t」が確定し「k」が残る）に Backspace を押すと、その打鍵だけを取り消して打ちかけを「t」に戻す。続けて `u` を打てば「つ」になる。Shift+英字やカーソル移動を挟んだときは取り消さず、ふつうに1文字消す。打った文字がかなになったとき（`k` `a` →「か」）の Backspace も「か」を消す。

### 入力モード（英数・かな）

- かなモードでは打った文字をローマ字としてかなにし、英数モードでは打ったとおりの文字（Shift や CapsLock もそのまま効く）を入れる。英数モードでも打つそばから変換し、英数字の文節として扱う
- 呼び出したときのモードは、トレイメニューの「起動時の入力モード」で「かな」（既定）・「英数」・「IME に合わせる」から選ぶ。設定は `settings.json` に保存し、呼び出すときに Rust 側で決めて "summon" イベントで渡す
- 「IME に合わせる」では、ショートカットを押した時点の呼び出し元の OS の IME に合わせる。日本語入力ならかな、英字入力なら英数。トレイから開いたときや読めないときは、かなで始める
- オーバーレイの中では、掴みどころの左右の「a」「あ」を押すか、キーで切り替える。Mac の英数キー・Windows の無変換キーで英数、Mac のかなキー・Windows の変換キーでかな、Windows の半角/全角キーで切り替え。macOS の英数・かなキーは WebView の中では入力メソッドが先に取って JS に届かないので、Rust 側（`platform`）で NSEvent のローカルモニタを置いて受け取り、"lang-key" イベントで渡す。オーバーレイに来たものだけを止めるので、OS の入力ソースは変わらない。無変換・変換に「IME オフ・オン」を割り当てていると、キーの名前が付かず（Unidentified）物理的な位置の `Lang2`・`Lang1` で届くので、名前と位置の両方で見分ける
- オーバーレイの英数・かなは、呼び出し元の OS の IME と同期しない（呼び出したときに読むだけ）。切り替えるたびに呼び出し元の IME を変えると、Windows 11 の IME はフォーカスが戻ったときに状態を上書きして当てにならず、閉じたときだけ変えると、いつ変わるのかが分かりにくいため
- 切り替えるときは、打ちかけのローマ字をそのまま確定させる

### 英字

- Shift を押しながら打った英字は、ローマ字にせず大文字のまま入れる（`Shift+U` `Shift+I` → 「UI」）。CapsLock の状態は見ない
- 英数字が続く部分（「UI」「MP3」）は辞書を引かず、まとめて1語として扱う
- 英字を含む文節の候補には、入れたとおりの表記のあとに、大文字・小文字・先頭だけ大文字・全角を並べる。入れたのと違う書き方にしたい語（Shift で打った「NPM」を「npm」に）は、打ってからホイールで選ぶ

### 数字と記号

- 半角数字の並びは辞書を引かず、数の品詞を持つ1語として扱う。後ろの助数詞と1文節にまとまる（「1000円」「3時」）
- 数字の直後の「.」「,」は「。」「、」にせず半角のまま入れ、数字の一部として扱う（「3.14」「1,000」）
- ローマ字入力で日本語の記号になるもの（「、。ー・「」～？！」）は、その文節の候補に元の半角と全角を並べる（「。」→「.」「．」）。「ー」は記号だけの文節のときに限る（「ラーメン」を書き換えない）
- そのほかの記号は、半角と全角を入れ替えたものを候補に並べる（「@」→「＠」）
- Space は半角スペースを入れる（打つそばから変換するので、変換のキーは要らない）。全角スペースはホイールで選ぶ

## 学習

ユーザーが確定時に選んだ候補を覚え、次回から上位に出す。
学習が原因で入力が重くなることを避けるため、次の制約を守る。

- 学習データは件数に上限を設ける（初期値 1万件）。超えたら最も古く使われたものから捨てる
- 変換中に参照するのはメモリ上のハッシュ表だけ。変換中にファイルを読み書きしない
- ファイルへの保存はオーバーレイを閉じたあとに、別スレッドでまとめて行う。一時ファイルに書いてから置き換え、途中で落ちても壊れないようにする
- ファイルが壊れていたら捨てて空から始める。起動を失敗させない
- 学習をリセットする手段を用意する（トレイメニューの「学習をリセット」）
- 学習データが上限まで溜まった状態でもベンチマークで速度を確認する

## セキュリティ

- 使用中は通信しない。キー入力はオーバーレイにフォーカスがあるときだけ受け取り、OS 全体のキー入力を監視しない
- 画面は CSP で、同梱のファイルと Tauri の呼び出し以外を読み込めないようにする（開発中は Vite の都合で外す）
- 辞書と学習データは、壊れていたり細工されていたりしても、読み込み時の検査で弾くか空から始める
- 学習データ（`history.tsv`）は確定した読みと表記を平文で持つ

## 0.2.0 で入れる予定（学習とユーザー辞書）

ユーザー辞書・文節区切りの学習・文脈つきの学習を 0.2.0 にまとめて入れる。作る順は、ユーザー辞書 → 区切りの学習 → 文脈つきの学習（区切りの学習はユーザー辞書の仕組みを使い回す）。3つとも実装済み。オーバーレイの候補の行（当時は下段）から辞書に登録することもできる。

エンジンは学習とユーザー辞書をまとめた `UserData` を受け取る。アプリは1つのロックで持ち、保存は専用のスレッドで学習（`history.tsv`）とユーザー辞書（`user_dictionary.tsv`）を別々に書く。

### 2つの層に分ける

| 層 | 決めること | 入るもの |
|---|---|---|
| 語の層（ラティス） | 区切りと第1候補 | システム辞書・ユーザー辞書・区切りの学習 |
| 並びの層 | 同じ範囲の候補の順 | 文脈つきの学習・今の学習（文脈なし） |

並びの層は区切りを動かさない。学習で文が勝手に区切り直されないようにするため。

### ユーザー辞書

- 登録した語（読み・表記・品詞）をシステム辞書の語と同じくラティスに足す。1語として入るので、その文字列の内側では区切られにくくなる
- ラティスを作るとき、位置ごとに、登録した一番長い読みの長さまで読みを切り出して表を引く。読みは 32 文字まで、表記は 64 文字まで
- コストは 2000（`USER_WORD_COST`）。実際の辞書で、単独の「すずり」「かい」は登録した語になり、ほかの語の一部の読み（「きたなかった」→汚かった、「かいぎ」→会議、「にかいめ」→2回目）には割り込まないことを確かめた（`examples/bench.rs`）
- 品詞は名詞・人名・地名・組織名の4つ。Mozc の品詞IDは dictgen がバイナリ辞書に書き込む（形式 `SZRDIC02` の6つ目の領域）
- 読みはひらがな・「ー」・英数字・記号（文字でも空白・制御文字でもないもの）を受け付ける。スペースは変換で必ず文節の切れ目になるので入れられない。カタカナはひらがなに、全角の英数字・記号は半角にそろえる（設定画面で IME が全角のまま打っても登録できるように）
- 引くときは読みを1文字ずつそろえる（`fold_char`）。英字は小文字に、全角は半角に、ローマ字入力で日本語の記号になるもの（「、。「」・ー」と「〜」）は元の半角にする。「npm」で登録した語を Shift で打った「NPM」でも、「[えすえふ]」で登録した語をかなモードで打った「「えすえふ」」でも出す。ラティスを作るときに読み全体を一度だけそろえて引く。同じ読み・表記・品詞の語は重ねて登録しない
- 学習とは別のファイル（`user_dictionary.tsv`、1行に「読み TAB 表記 TAB 品詞」）に保存する。件数の上限で捨てず、「学習をリセット」でも消さない。読めなかったときは `.tsv.broken` に退避してから空で始める（手で登録した語を上書きで失わないように）
- 設定画面を「一般」「ユーザー辞書」の2つのタブに分ける（ウィンドウは 480×600）。ユーザー辞書のタブは、上に追加の欄（読み・表記・品詞）、下に新しい順の一覧と編集・削除のボタンを置く。編集を押すとその行が表記・読み・品詞の入力欄になり、Enter か「保存」で書き換え、Esc か「やめる」で戻す。書き換えても一覧の位置（登録した順）は変えない。ほかの登録済みの語と同じになるときは書き換えない
- 学習1万件・ユーザー辞書1000語（読みは上限の32文字）の状態で、34文字の文の変換は約 5ms（登録なしとほぼ同じ）
- オーバーレイの候補の行から登録する。変換したあとの表記ごと登録できるよう、候補の行からだけにする（ひらがなの行は読みだけなので登録しない）
  - 候補の行の文節を右クリックしたら、その文節だけをすぐ登録する。右ドラッグで複数の文節にまたがったら、それらをつないだ読みと表記で登録する（ひらがなの行の「右ドラッグで1文節にまとめる」と同じ形）。macOS は Control+クリックも右クリックとして扱う
  - 表記は今選んでいる候補。末尾の助詞・助動詞は除く（「スズリで」は「スズリ」。区切りの学習と同じく文節の読みだけのラティスで分ける）。品詞は名詞にする（変えたければ設定画面で消して登録し直す）
  - 登録したら、下の案内の欄に重ねて1行だけ「ユーザ辞書に「（登録した語）」を登録しました。左クリックでキャンセルできます。」を5秒出す（文字は青）。語が長くて1行に収まらないときは、語の末尾だけを「…」で省略し、前後の文は省かない。マウスを乗せている間は残りを5秒に戻して止め（円も満ちた状態で止める）、離したらそこから5秒数え直す。先頭に円グラフのような印を出し、5秒かけて欠けていく。左クリックすると登録を取り消して消す。登録できなかったとき（同じ語がある、読みに使えない文字があるなど）は、その理由を同じ場所に5秒出す
  - 当初は「文節に乗せて Ctrl+D で登録欄を出し、Shift+←→ で隣の文節を足し、品詞を選んで Enter」という案だった。登録欄を出さずにすぐ登録し、取り消しの知らせを出す形にした

### 文節区切りの学習

- 確定したとき、手で置いたピン（`pinned`）に接する文節を「学習した語」として語の層に足す。自動で増えるユーザー辞書として扱う
- 効き方は「次からその区切りになりやすい」程度にする。必ずその区切りにすると、ほかの文で誤って効いたときに直しにくい
- 文節は助詞を含む（「会議で」）ので、覚えるときに先頭と末尾の品詞を求め直し、前後とのつながりのコストを保つ
- 1文字の文節は覚えない（短い読みがほかの文で効きすぎないように）。件数に上限（1万件）を設け、古く使ったものから捨てる
- 覚えるとき、文節の読みだけでラティスを作り、選んだ表記になる単語の並びを探す。見つかれば、先頭の左文脈ID・末尾の右文脈ID・内側のコスト（単語と内側のつながりの合計）から 1000 引いたもの（`LEARNED_BONUS`）を覚える。覚えた語自身を見て下げ続けないよう、このラティスには覚えた語を入れない。見つからない表記（カタカナ・ひらがなのままなど）は名詞・コスト 4000 で覚える
- 画面は、確定するときに各文節が手で置いたピンに接するか（`manual`）を渡す
- `learned_words.tsv`（1行に「時刻 TAB 読み TAB 表記 TAB 左文脈ID TAB 右文脈ID TAB コスト」）に、学習データと一緒に保存する。「学習をリセット」で一緒に消す。辞書を作り直して品詞IDの数が変わったら、範囲外のものは使わない
- 辞書に付属語（助詞・助動詞）の印を持たせる（形式 `SZRDIC03` の7つ目の領域）。文節の候補を作るとき、末尾の付属語を除いた自立語の表記も求める（文脈つきの学習で使う）
- 実際の辞書で、「第2｜会議室で」を手で1文節にして確定すると次から「第2会議室で」になり、「いちぶん」を「一文」で確定すると同じ文では「一文」になるが、「いちぶんずつよむ」は「1分ずつ」のまま（効きすぎない）ことを確かめた
- 学習1万件・区切りの学習1万件（読みは32文字）・ユーザー辞書1000語で、1文の変換は最大 6.5ms。区切りの学習の書き出しは 1.1MB・2ms

### 文脈つきの学習

- 確定したとき、2番目以降の文節について「前に出た自立語・読み → 選んだ表記」を覚える。新しく覚えるのは第1候補以外を選んだときだけで、第1候補のまま確定したら覚えているものの時刻だけを更新する（今の学習と同じ）
- 変換のとき、文節を左から作りながら、前の文節の第1候補の自立語と読みで引き、あればその表記を先頭に出す。優先は、直前の自立語 → 前に出た自立語 → 文脈なし → エンジンの順
- ホイールで直前の文節を替えても、後ろの文節の候補は入れ替えない（「候補を切り替えると後ろの文が動く」負担をなくす狙いに合わせる）。覚えるときは実際に選ばれた表記で覚える
- `context_history.tsv`（1行に「時刻 TAB 種類 TAB 文脈 TAB 読み TAB 表記」。種類は直前 a・前に出た t）に、学習データと一緒に保存する。当初は `history.tsv` に列を足す案だったが、今の学習の形式を変えずに済むよう別のファイルにした。「学習をリセット」で一緒に消す
- 上限は5万件（約 2.3MB）。今の文脈なしの学習は残す（文の先頭や初めての組み合わせで効くため）
- 文脈の単位は、細かい順に「直前の文節の自立語（「会議で」「会議の」はどちらも「会議」）→ 同じ入力の中でそれより前に出た自立語（話題として効く）→ 文脈なし」と引き、最初に見つかったものを使う。広く見ても速度は問題にならず（表を引く回数が増えるだけ）、決め手は学習が効く機会の多さ（細かい文脈ほど同じ場面に出会わず効かない）。使ってみて足りなければ見直す
- 自立語は、辞書の付属語（助詞・助動詞）の印で、末尾の付属語を除いて求める。確定したときは区切りの学習と同じく文節の読みだけのラティスから求め、変換のときは候補を作った単語の並びから求める（並びの分からない学習の候補は、最良の並びと同じ付属語で終わっていれば除く）
- 「前に出た自立語」との組み合わせは件数が増えやすいので、第1候補以外を選んだときだけ覚え、5万件の上限の中で古いものから捨てる
- 実際の辞書で、「人体の」のあとで「器官」を選ぶと次から「じんたいのきかん」が「人体の｜器官」になることを確かめた。「前に出た自立語」は3文節以上の文で選んだときに覚える
- 学習1万件・区切りの学習1万件・文脈5万件・ユーザー辞書1000語で、1文の変換は最大 5.5ms。文脈つきの学習の書き出しは 1.8MB・16ms で、その間は学習の表をロックする（保存は閉じたあとなので、入力を待たせることはまずない）

### 容量と速度

- 学習データは全部で数 MB に収め、100MB を超えないようにする（2026-11 時点の `history.tsv` は 136件・3.8KB、1件約 28 バイト）
- 変換中はメモリ上の表を引くだけにする。ユーザー辞書と区切りの学習は文字の位置ごとに数十回、文脈つきの学習は文節ごとに1回
- 今の保存は全件を書き出す間、学習の表をロックする。件数が増えると次の変換を数 ms 待たせうるので、上限まで溜めたベンチマークで確かめ、必要なら複製してからロックを外して書き出す

## 後回しにすること

- 前回の履歴を複数件保存すること
- 変換操作の取り消し（Undo）
- 貼り付けた漢字を読みに戻す（案）。上段で漢字を含む文節にマウスを乗せてホイールを回すと読みの候補（「今日」なら「きょう」「こんにち」）を並べ、選ぶとその文節をひらがなに戻して、下段でふつうに変換や候補の切り替えをできるようにする。見送った理由は次のとおり
  - 今の辞書は読みから引く作りなので、表記から読みを引く索引（表記の fst と単語の番号の並び）を dictgen で足す必要がある。辞書は 48MB から 10〜15MB ほど増える見込み
  - dictgen・エンジン（表記の並びから読みを求める Viterbi）・画面の3か所に手が入り、エンジンのテストとベンチマークも要る
  - 読みが複数ある語は候補から選ぶ形になり、辞書にない固有名詞は読みを出せない
